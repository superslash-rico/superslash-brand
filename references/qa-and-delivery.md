# 验收与交付

## 开始生成前

确定输出格式、尺寸、受众和实际内容，读取相关格式技能。若该技能要求 artifact operation marker，在本次首次生成前按其要求执行；不要在品牌技能中另加重复 marker。实际授权与用户要求决定覆盖、上传和发布，不以测试或技能触发推定外部写入。

## 生成后的检查

1. 回读文件内容，核对事实、标题、数字、单位、目录、来源与用户要求的完整内容。检查模板中的样例身份和字样已经合理替换。
2. 渲染全部页面；先看整册节奏，再逐页按可读尺寸查看。确认封面与尾页、层级、对齐、留白、断行、表头、人物和二维码均正常。缩略图与文本提取只作辅助。
3. 对照选定版本的原稿检查 Logo、底色、比例、留白与火点，再核对字体、页码、链接、书签或目录、表格分页以及图片质量。按 [官网首页风格](homepage-style.md) 检查封面、内容层级和装饰密度。海报增加手机宽度缩小检查。
4. PDF 检查实际使用字体是否嵌入；Word/PPT 检查原生文字、表格和图表，回读最终导出文件。QR 验证可解码且指向正确链接。
5. 修复源文件或制作代码，再渲染受影响页面；检查与共享页眉、样式、组件相关的其他页。只有最终版通过检查后才能交付。

`scripts/check_artifact.py FILE [--expected-pages N] [--format a4_portrait|a4_landscape|slide_16_9] [--require-mi-sans]` 可作只读结构检查：PDF 尺寸、字体嵌入、页面文字；DOCX 原生段落与表格、东亚字体、尺寸、页眉页脚；PPTX 尺寸、原生文字/表格/备注及字体。它不渲染、不解 QR，也不证明审美或目标应用行为。结构结果与逐页视觉检查共同构成验收。

## 可维护性

使用相对于技能与本次任务的路径，素材完整性可用 `scripts/brand_assets.py --verify` 检查。不同文档的尺寸、主题与内容存在各自实例中，不能共享可变全局变量。长表需要真正跨页，不能截断或按固定行数丢数据。

技能更新时验证典型场景，而非只检查 Markdown 语法：A4 客户方案、A4 内部报告、16:9 汇报。验证内容完整、原生可编辑、字体与比例、Logo、页眉页脚、封面尾页和输出路径；加入跨页表格或长标题等与变化有关的边界案例。不要为简单可逆文字修改增加无关的测试流程。

## 文件组织

遵循用户现有目录；此项目课程介绍与海报保持分开放置。新场景在自己的目录交付，制作源和私有渲染另存，不混入客户成品。默认只把当前任务的最终版本交付给用户，不自动删除旧文件。

交付报告说明做了什么、输出格式、实际验证范围与会影响使用的限制。提供可编辑源文件（如任务需要）与适合分发的 PDF。不要声称未经实测的应用兼容性，也不要把本地渲染或结构检查描述为真实客户验收。
